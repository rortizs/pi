# Requerimientos No Funcionales

## Seguridad

| ID | Requerimiento |
|----|---------------|
| RQNF-001 | El sistema debe aplicar deny-by-default para acciones destructivas o fuera de alcance. |
| RQNF-002 | El sistema debe minimizar persistencia de datos sensibles. |
| RQNF-003 | El sistema debe diferenciar análisis, recomendación y ejecución. |

## Arquitectura

| ID | Requerimiento |
|----|---------------|
| RQNF-004 | La arquitectura debe favorecer separación por dominios y responsabilidades. |
| RQNF-005 | Debe ser posible agregar nuevos agentes o perfiles sin romper los existentes. |
| RQNF-006 | El sistema debe crecer por composición de agentes, no por un prompt monolítico. |

## Calidad

| ID | Requerimiento |
|----|---------------|
| RQNF-007 | Las conclusiones de seguridad deben ser verificables por terceros. |
| RQNF-008 | El sistema debe evitar presentar hipótesis como hechos confirmados. |
| RQNF-009 | Los artifacts clave deben vivir en formatos persistentes y compartibles. |
